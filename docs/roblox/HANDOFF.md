# Handoff: АРМ ДСП simulator -> Roblox

Everything a fresh Claude Code session needs to know that is not obvious from the code.

## 1. Product
Browser training simulator of a station dispatcher's workstation (АРМ ДСП).
Player = the dispatcher: sets train/shunting routes, controls switches and signals,
reacts to timetable, faults and radio calls. Time is simulated (1 s step).
Static site, no backend. Live artifact + repo exist; repo is the source of truth.

## 2. Stations in the browser version (11)
sokologirne (main, double-track line Melitopol–Dzhankoi), berdyansk (dead end, port, much shunting),
zaporizhzhia2, and the "line" stations: mamut, soloneozero, sivash, salkove, novooleksiivka,
henichesk (route "sh"); dnipro, amur (route "dn").
Line mode = several neighbouring stations played together (each by one player or bot).
**Roblox plan: port ONE station first - henichesk (small, dead end), then sokologirne.**

## 3. Architecture of the reference code
- Station data: `StationKit.build({meta, nodes, switches, edges, info, signals, park, lines, labels, view})`.
  - `nodes`: id -> [x,y] (schematic coordinates, not geographic).
  - `switches`: [id, node, commonNode, plusNode, minusNode, label, opts]. "+" = straight.
  - `edges`: [nodeA, nodeB, sectionId]; sections are track circuits (named after switches, e.g. "1СП").
  - `park`: station tracks with length and end signals (sigL/sigR).
  - `signals`: entry / exit / shunt, with node + direction (L/R).
  - Routes are GENERATED by following switches from each signal (train routes entry->track, track->line;
    shunting routes signal->signal). So only topology needs porting; routes come from `build`.
- `engine.js` `createSim(T, SCHEDULE, PARAMS, opts)`: deterministic, 1 s steps, no DOM.
  Handles route setting, locking, hostile routes, train movement, journal, faults, radio.
- Timetable: `generator.js` builds a daily schedule from a variant number (electric trains with stop,
  passenger, Intercity, freight with overtaking; sparse/medium/dense traffic), seeded RNG.
- `net.js` = browser multiplayer (PeerJS). Irrelevant for Roblox: use RemoteEvents instead.

## 4. Mechanics to reproduce (handbook pp. 136-166)
- Route setting: click start signal -> "set train/shunting route" -> click end signal.
  Switches move ~4 s (number blinks), sections get route colour, then get locked (light-grey fill), signal opens
  (green = train mode, white = shunting mode).
- Cancellation of a route needs time-delay sets: free 6 s, shunting 60 s, train 180 s.
- Artificial release (ІР) 3 min; invitation signal (<=20 km/h); auxiliary switch transfer when a section shows false occupancy
  (bypasses route locking, with counters of responsible commands); blocking of signals/switches/sections with a reason.
- Responsible commands ask for a vigilance code.
- Training faults: false occupancy of a section, loss of switch control ("РОЗРІЗ СТР.").
- Operating modes: main / reserve / auxiliary. Wrong switch position under a train = derailment or collision, the day restarts.
- Train radio (telegram forms per instruction ІРП ЦД-0058, chapter 9) and driver calls at closed signals.
- Trains: dead-end station => all trains terminate and return; loco-hauled trains need a runaround.

## 5. UI that was approved (keep behaviour)
Square black/white АРМ scheme. Interaction windows are approved by the user and must keep their behaviour:
object panel for signal/switch (list of routes: set / open-close / cancel), train card, confirmation dialogs,
block-reason dialog, radio window, help. Two scheme looks existed (smooth / console-like).
Checks that existed: no label may overlap a track, switch or other label (automatic overlap checker).
Languages: Ukrainian + Polish.

## 6. Decisions and preferences
- Keep station plan layout as on the real plan; realism over convenience.
- User first rejected a "Windows 7" GUI style; wants the plain black/white АРМ look.
- Security is a top priority; the code is intended to become closed source later.
  On Roblox this is natural: sim and data live on the server, clients get only state; validate all remote input.
- Multiplayer was postponed in the browser version; on Roblox it is likely wanted from the start (server-authoritative).
- Copyright: font is GNU Unifont subset (OFL 1.1); no third-party assets. Do not copy real-company logos or
  protected material into the Roblox game. Check Roblox asset rules before using any imported audio/images.

## 7. Roblox-specific porting notes (suggestions, verify in Studio)
- JS -> Luau: station files are plain data tables -> ModuleScripts. `engine.js` (~85 KB) is the main port job;
  port in pieces: topology/derive -> routes -> locking -> train movement -> faults -> radio.
- Scheme drawing: use a ScreenGui with Frames/lines (or ViewportFrame/EditableImage for many segments).
  Avoid creating thousands of instances; update only changed elements (the browser version is dirty-checked).
- Server runs the sim tick (1 s, task.wait / Heartbeat accumulator). Clients send commands via RemoteEvent;
  server validates and replies with state diffs, not full state each tick.
- Mobile support matters (Roblox has many phone players): big touch targets, pan by drag.
- Text: Cyrillic works in Roblox fonts; keep the UI strings in one table (like `i18n.js`).
- A browser "scheme view" can later also be shown on a 3D workstation model (SurfaceGui) - optional.
